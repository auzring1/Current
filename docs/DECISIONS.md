# Decision log

Defaults chosen during planning. Each entry can be overridden. Entries marked **OWNER** are yours to decide; the others are engineering defaults.

## Engineering defaults
| # | Decision | Rationale |
|---|---|---|
| D1 | Go for agent and server, single module | Shared protocol/crypto/version code; static binaries; good Windows API access |
| D2 | gRPC bidi stream over TLS 1.3 mTLS | Typed and versioned; flow control; keepalive; low idle cost |
| D3 | Gateway terminates mTLS on its own port; not behind Caddy | Avoids proxy-forwarded client-identity vulnerabilities (SECURITY T-NET-3) |
| D4 | No SQLite dev mode | One SQL dialect; dev compose gives Postgres in one command |
| D5 | sqlc + pgx + goose | Compile-time-checked parameterized SQL; embedded forward-only migrations |
| D6 | ~~OpenAPI spec-first + oapi-codegen~~ **Revised in Phase 1:** `api/openapi.yaml` is the contract; Go handlers are hand-written with strict decoding (unknown fields rejected, size limits, explicit validation); `TestRoutesMatchSpec` fails the build if routes and spec drift; TypeScript types are generated from the spec | Generated Go server stubs added awkward types and a large dependency surface (kin-openapi) to the shipped binary; the drift test keeps the single-source-of-truth benefit |
| D7 | Mantine + TanStack + Vite; SSE for live updates | Permissive license, CSP-nonce support, data-grid friendly; SSE is simpler and safer than WebSockets |
| D8 | Root CA protected by owner passphrase, issuing CA and job-signing key encrypted with KEK | Separates TLS trust from job-signing trust; root operations are rare and deliberate |
| D9 | Ed25519 for job signatures; P-256 device keys (TPM-compatible) | Small, fast, deterministic; TPM 2.0 supports P-256, not Ed25519 |
| D10 | Device certificates 90 days, renew at 1/3 remaining, 180-day expired-renewal grace | Short-lived certificates without stranding laptops that have been offline |
| D11 | winget is a metadata source only; our own installer engine executes | The winget CLI is unsupported as SYSTEM (see research note) |
| D12 | Per-user app policy default = `report_only` | Safe default; admins opt in to changes |
| D13 | User-scope staging: SYSTEM-write, user read/execute (stricter than the brief's "user + SYSTEM writable") | Users don't need write access; removes a TOCTOU window |
| D14 | Logon fallback uses SYSTEM-principal task + named event, not a user-principal task | No user→SYSTEM IPC channel to attack |
| D15 | Self-update via A/B slots + `ImagePath` switch + scheduled rollback check | Survives a broken new binary without an extra resident watchdog process |
| D16 | Third-party installers downloaded from vendor URLs by default; server caching opt-in | Avoids redistribution-licensing problems by default |
| D17 | Agent-local policy ceiling set at install time | Limits blast radius of a server compromise |
| D18 | Audit log hash chain + insert-only role | Makes tampering evident without external infrastructure |
| D19 | Caddy (not Traefik) for the GUI | Simpler config, automatic HTTPS, built-in internal CA for LAN mode |
| D20 | bbolt for agent local state | Pure Go, tiny, transactional; no CGO |
| D21 | Linters: `go vet` + `staticcheck` + `gosec` (Linux and Windows builds) + project semgrep rules, instead of golangci-lint | golangci-lint 2.14 cannot yet analyze Go 1.26+ code; revisit when it supports our toolchain |
| D22 | Toolchain Go 1.27.1 (`toolchain` in go.mod), `go 1.26` language level (required by dependencies) | Latest stable compiler for security fixes |
| D23 | Agent polls enrollment status every 60 s (±20 s jitter) while pending approval, not 5 min | Approval in the console takes effect within about a minute; cost is one small request per pending device |
| D24 | Agent decides certificate renewal on server-corrected time (offset from HelloAck) | A wrong local clock caused renewal loops in testing; the server clock is the reference |
| D25 | Job-signing EKU OID `1.3.6.1.4.1.32473.7231.1.1` (documentation PEN) until a real PEN is registered; agents will accept both during the transition | Go cannot encode 128-bit `2.25` UUID arcs in certificate EKUs, so a registered PEN is the clean fix |
| D26 | X-Forwarded-For trusted only from Caddy's fixed container IP (`AUZ_CADDY_IP/32`), not the whole Docker network | The Docker bridge gateway sits inside the network range; trusting the range allowed a forwarded-IP spoof path |
| D27 | Breached-password check uses an embedded list (46k entries ≥ 12 chars from SecLists, MIT) | Offline, no phone-home (O9); NIST 800-63B-style policy without composition rules |
| D28 | Database traffic between server and PostgreSQL is not TLS-encrypted inside the internal Docker network | Same host, internal-only network with no published port; TLS to Postgres is planned for split deployments (Phase 6) |
| D29 | **Temporary pin:** `google.golang.org/grpc v1.85.0-dev.0.20260825072537-93e31b48545e` (pre-release snapshot) | Fixes GO-2026-6443, an unauthenticated server panic (missing `:authority`/Host) reachable on our internet-facing gateway listener. No stable release contains the fix yet. **Move to v1.85.0 as soon as it is tagged**; govulncheck in CI enforces that no called vulnerability remains |
| D30 | sqlc cannot parse multi-argument `unnest`; `db/sqlc_stubs.sql` declares `unnest(anyarray, …)` (2–15 args) **for sqlc only** and is never run against a database | Lets batch upserts of thousands of inventory rows stay one parameterized statement without hand-written pgx code |
| D31 | The agent persists a **hash snapshot** (item key → sha256) plus the acknowledged revision, and commits it only on the server's `Ack` | Constant small memory and disk (no second copy of the inventory); a lost connection can never leave agent and server silently disagreeing, because Hello revisions are compared on reconnect |
| D32 | A failed scan group (e.g. a locked offline hive) keeps its previous items in the snapshot; its absence is never reported as removal | A transient read error must not look like an uninstall of everything for that user |
| D33 | AppX/MSIX inventory is read from the registry (`AppxAllUserStore`), best effort; WinRT `FindPackagesForUser` is deferred to Phase 3 | The registry layout is undocumented but readable from Go without WinRT bindings; Phase 3 needs WinRT for MSIX installs anyway and will revisit. Counts are logged by the Windows CI probe |
| D34 | Title normalization on the server (not the agent), keeping the raw name per install | Rules can be improved and re-applied without touching 10k agents; the raw name stays the source of truth |
| D35 | Dynamic groups only in Phase 2; static groups and per-site scoping move to Phase 3 | Phase 2 needs groups for filtering and reporting; static membership matters once deployments target groups |
| D36 | Group filters are a typed JSON tree compiled to parameterized SQL with allow-listed fields, comparators, depth/node/value limits and a read-only 10 s statement timeout | A user-defined filter must never be able to inject SQL or run an unbounded query |
| D37 | `software_history` is a plain table in Phase 2; monthly partitioning and retention move to the Phase 6 load tests | Not needed at demo scale; the real write rate is unknown until the 10k-device test |
| D38 | CSV exports neutralize formula injection (leading `= + - @ TAB CR` prefixed with `'`), carry a UTF-8 BOM, are streamed, capped at 2M rows and audited | Inventory strings come from endpoints and are untrusted; spreadsheets execute formulas |
| D39 | New RBAC permissions `groups:read`, `groups:write`, `inventory:export` (read-only role gets `groups:read` only) | Exporting the whole fleet's software list is a bulk-data action and should not be implied by read access |
| D40 | Offline user hives are loaded from a **temporary copy** (hive + transaction logs) under `C:\ProgramData\Auzring\tmp`, never directly | A Windows CI test showed `RegLoadAppKey` with a read-only mask rewrote the hive file. A management agent must not modify a user's profile; the cost is a few MB of copy per offline user per scan |
| D41 | The catalog imports **winget manifests from the `microsoft/winget-pkgs` repository on GitHub** (raw files, one package and version per import) instead of syncing the signed winget CDN index (design §7.1 step 1). Search covers imported packages, a shipped suggestion list and an exact-identifier probe of the repository | The CDN index (`source2.msix`) format and its signature chain could not be verified from this build environment, so building on it would be guesswork. The manifests are the same data, are plain text, and every installer is still pinned by the SHA-256 inside the manifest. Index sync with signature verification stays on the list (needs a probe from a network that can reach the CDN) |
| D42 | Content download is a **gRPC server-stream (`FetchContent`) on the existing mTLS channel**, not `GET /v1/content/{sha256}`. It serves only uploaded (custom) installers, only to a device holding a live job that names that hash, with resume by offset, 256 KiB chunks and a per-device concurrency limit | One transport, one authentication path and no second listener to harden. Vendor installers are never proxied (D16) |
| D43 | Custom (uploaded) packages are **not subject to the unverified-package confirmation**; winget packages are, until they have a passing VM-matrix result for the scope | The administrator supplied the file and takes responsibility for it, which is the premise of custom packages. The hash, optional signer pin and Authenticode check still apply |
| D44 | User-scope staging root is `%ProgramData%\AuzringStage\<SID>\<job>` (traverse-only root, SYSTEM/Administrators write, that user read/execute); machine staging stays under the agent data directory | The helper runs as the user and must read the staged installer; the data directory is SYSTEM-only (D13) |
| D45 | The **service runs the whole install pipeline** (download, hash, locked re-hash, Authenticode, exit-code mapping, detection). The user-context helper only starts the already-verified command in the user's session, after re-verifying the signed envelope, the SID, staging containment and the file hash itself (design §8 had the helper run the full engine) | Keeps one copy of the pipeline running as SYSTEM, makes the helper tiny, and a lying helper can only affect the same user. Detection after the run is done by the service |
| D46 | MSIX/AppX installers are marked **unsupported** in the catalog (`catalog_installers.unsupported`) and cannot be deployed in Phase 3 | The `PackageManager` WinRT path needs real-VM work; the console shows why an installer is not deployable instead of failing at runtime |
| D47 | Per-user app policy is resolved **package override → organization default** (`org_settings`); group-level policy is deferred | Groups do not carry policy yet. The console shows the effective value and its source |
| D48 | Dependency chains exist only for `convert_to_machine` (`jobs.depends_on`). A dependent job is dispatched only after its parent succeeded and is cancelled if the parent fails. Manifest `PackageDependencies` are stored but **not** resolved into sub-jobs | Covers the safety-critical case (never remove a user's copy unless the machine install worked). Full dependency resolution needs a graph and a failure policy that Phase 3 does not exercise |
| D49 | Jobs are **signed at dispatch time and re-offered with a fresh nonce until the agent acknowledges them**; an already-held job offered again is not a replay | The signing key may rotate and an offer can be lost on a dropped stream; the agent's ledger is keyed by job ID, so at-least-once delivery stays idempotent |
| D50 | A self-updating package (overlay `self_updating`) cannot be targeted by an **update** deployment, and per-user "update in place" skips it, unless the package's `self_update_policy` is `enforce` | Fighting a vendor updater causes version flip-flop. The more elaborate loop guard (suspend after a flip-flop is observed) is deferred |
| D51 | Large uploads (up to 2 GiB) are a single streamed `application/octet-stream` request to `/api/v1/catalog/content`; Caddy raises its body limit for that one path only (1 MB elsewhere) and the handler extends its own deadlines | Keeps the JSON API's small default limits for every other endpoint |
| D52 | The VM test matrix is a **harness plus an empty results file** (`test/vm-matrix`, `matrix_results.json`); nothing is "verified" until a human runs it on real VMs and commits the results | Claiming verification that did not happen would defeat the flag |
| D53 | An **update** removes older copies the new installer will not replace in place, and does it **before** installing: `Remove old X` jobs (one per older machine-wide row, chained) then the update, each linked with `depends_when = finished`. A copy counts as replaced in place when the new installer's detection rules name the same Uninstall key | Found in testing: updating a 7-Zip EXE install to the MSI left two copies. Removing first (not after) avoids an old uninstaller deleting the files of the version just installed, which share a folder. `finished` means a failed removal never blocks the update: the worst case is the old behaviour |
| D54 | Cleanup uninstalls carry `remove_older_than`: the **agent** re-reads the row's `DisplayVersion` and only removes it if strictly older (unknown or equal versions are left alone; a row that is already gone is success) | The server planned from a possibly stale inventory, and an in-place upgrade may have reused the key; the agent must never remove the version that was just installed |
| D55 | Only **revoked or retired** devices can be deleted (`DELETE /devices/{id}`, bulk `POST /devices/delete`). Deletion removes the device's certificates, inventory, jobs and group memberships; the audit log keeps the record (`device.delete`). The old certificates are gone, so an agent that still holds one is refused at the handshake | Revocation stays the safe, reversible-looking step; deletion is explicit and audited. Hardware identity is forgotten, so re-enrolling the same machine creates a fresh device |
| D56 | **Refresh** is an `INVENTORY_FULL` job (reused if one was requested in the last 2 minutes; only for online devices) that makes the agent send software and users, hardware if changed, and a heartbeat (uptime, reboot state, signed-in user) immediately | Same signed-job path as everything else: audited, subject to the agent's policy ceiling, visible on the Jobs tab. The 2-minute reuse stops the button from being a hammer |
| D57 | **Uninstall from inventory** creates ad-hoc jobs with no deployment and no catalog package; system components, AppX and portable rows are refused. **Missing updates** are computed from installed programs matched to imported catalog packages by normalized name and the package's effective (pinned) newest version; self-updating apps are listed as "vendor updates" and not deployable | Matches how administrators use the device page without forcing every program into the catalog. Matching by name is heuristic (D34): an unmatched program simply shows no update |
